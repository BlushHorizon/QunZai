## 3. 用户报的两个 bug（m452794）

> 「停止服务的时候 napcat 没有关闭，napcat 没有 QQ 链接的时候提示已连接」

### 3.1 停不掉 NapCat

**三个根因**：
1. `app/launcher.ps1` 的 `-Stop` 分支只杀 `server\server.js`，完全不管 `engine\`
2. `engine.js` `stop()` 只在 `this.startedProcess` 存在时才 kill，但 NapCat 是 `detached:true` 拉起的，不在进程树里
3. `server.js` `shutdown()` 没有调 `engine.stop()`

**修法**：新增 `killByInstallDir(dir)`——PowerShell 吐 `pid|CommandLine` 原始数据，JS 里归一再比，命中就 `taskkill /T /F`。

**★ 两个实测踩过的坑**：
- 不设 `[Console]::OutputEncoding=[Text.Encoding]::UTF8` 时 PowerShell 用 GBK 输出，中文目录 `D:\群崽\engine\napcat` 读回来是乱码，匹配恒为 0
- **匹配绝不能放在 PowerShell 里用 `-like`**：目录参数可能是 `D:/x` 而 CommandLine 是 `D:\x`，永不命中

**实测**：`POST /api/engine/stop` → `{"ok":true,"killed":[17340,652,13496,23276,17080,6756]}`，杀完剩余 **0**。

### 3.2 未登录却显示已连接

**根因**：`qq-adapter.js` 的 ws `open` 事件直接 `this.connected = true`——但「连上 OneBot WS 服务」≠「QQ 已登录」，NapCat 未扫码时照样接受 WS 连接。

**修法**：`open` 时先 `connected=false` + 广播「正在确认 QQ 登录状态…」，再 `get_login_info` 重试 4 次，用 `const uid = info && Number(info.user_id); if (info && uid)` 判真值（**防「回 user_id=0 空壳」这种最阴险的情况**）。

**实测**（起假 OneBot 服务 3002 双向验证）：未登录 → `needLogin:true` / 「QQ 未登录」；已登录 → `connected:true` / 「已连接：测试号(2296258484)」。

### 3.3 顺带修的第三个问题：端口被别的程序占着却报 running

用户机器上 3001 实为 `D:\SnowLuma-v1.14.22-win-x64\node.exe index.mjs`，群崽误报自己的 NapCat 在跑。

**修法**：新增 `portOwnerOf(port, dir)` 返回 `'ours'|'other'|'unknown'`；`status()` 里 `const dirForOwner = info?.dir || engineCfg.dir || ''`（**必须回落配置 dir，否则服务刚启动 info 为 null 时永远 unknown = 判断没生效**）。

### 3.4 第四个 bug（本轮最后发现）

`engine.js` `_anyOpen(info)` 只检查端口是否开放，不检查是谁开的。SnowLuma 开着 3001 就被当成「自己的运行时在跑」→ `start()` 直接返回 `alreadyRunning:true` 什么都不启动，用户点什么都没反应。

**修法**：`_anyOpen` 里 `const owner = portOwnerOf(p, info.dir); if (owner === 'other') continue;`

**实测**：SnowLuma 占 3001 时 `_anyOpen` 返回 **0**；`POST /api/engine/start` → `started:true`，NapCat 真的起来（4 个进程、6099 监听）。

## 4. 版本号 4 源分裂（结构性修复）

### 4.1 问题

版本号有 **4 个独立手写来源**：
- `app/package.json:3`
- `app/server/version.js:4`
- `app/public/index.html` 的 `#appVersion` 与 `#aboutVersion`（两处）
- `app/setup.nsi:17`

`build-package.js` 只读 `package.json` 用于命名 exe，`copyDir` 原样拷贝 → **每次升版 HTML 必然停在旧值**。
页面之所以还能显示对，全靠 `app.js:245-250` 运行时覆盖 DOM——**属补救不是修复**，首帧会闪旧号。

### 4.2 修法

`build-package.js` 新增 `VERSION_TARGETS`，打包时正则注入 `VERSION`；**找不到注入点就 `process.exit(1)` 拒绝打包**（版本号对不上是发版事故）。

**反向验证做过**：把源码故意改成 `1.4.9` → 打包日志 `✓ 版本号统一为 v1.4.14（3 处更正，0 处本就正确）`。

### 4.3 ★ BOM 坑（反复踩了 3 次）

`edit` 工具会吃掉 UTF-8 BOM。`setup.nsi` 被吃后 makensis 报 `Bad text encoding`；`launcher.ps1` 被吃后 PowerShell 报 12 个语法错误。
**修法**：Node 脚本检查 `b[0]===0xEF && b[1]===0xBB && b[2]===0xBF`，缺则补回。
**检查命令**：`head -c 32 setup.nsi | xxd`（应为 `efbb bf3b`）。

## 7. 扫码后没连上（m452108）——三个根因

| 根因 | 说明 |
| --- | --- |
| 只给「设置里记着的老账号」写 OneBot 配置 | `_ensureNapCatConfig()` 有 account 就只写 `onebot11_<老号>.json`，**从不写公共模板 `onebot11.json`**。NapCat 照模板给新号派生，没模板 → 派生空配置 → 3001 永不监听 |

## 14. 教训清单（写给未来的自己）

1. **`Number(x) || default` 吞掉合法 0** —— 本项目复发 3 次，一律用 `Number.isFinite` 判
2. **`\W` 在 JS 里是非 ASCII 单词字符**，汉字全在里面，用它判中文噪音必错
3. **只看端口不看归属** —— 端口开着不等于我们的程序开着
4. **PowerShell 中文**：必须设 `[Console]::OutputEncoding=UTF8`；脚本文件必须 UTF-8 with BOM；匹配逻辑放 JS 不放 PowerShell
5. **`edit` 工具吃掉 BOM** —— 改 `.nsi` / `.ps1` 后必须检查补回
6. **源码目录 ≠ 用户跑的那份** —— 改完必须 `cp` 到 `D:\群崽`，且确认进程启动时间晚于文件 mtime
7. **PowerShell curl 发中文 JSON 会乱码** —— 用 Node `fetch` + `Content-Type: application/json; charset=utf-8`
8. **静默失败是最难查的** —— 任何 `return` 都要广播一个可观测事件
9. **越线发版教训**：`main` 就是发布通道，push 即上线。用户说「先测试」时**连 commit 都要谨慎**
