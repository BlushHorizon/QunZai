## 本版内容

### 修掉启动时的黑色命令行窗口

以前每次打开群崽，任务栏都会闪一下（在 Windows Terminal 下是一个标签页），标题是 `node.exe` 的完整路径。看着像出了错，其实不影响使用，但很烦。

原因不在群崽自己——`QunZaiHost.exe` 是无窗口程序，它拉起的 `node server\server.js` 也带 `CreateNoWindow`。真正开窗的是**内置 NapCat 内部 fork 的 worker 子进程**：它在创建 worker 时用了 `stdio: ["inherit", "pipe", "pipe", "ipc"]` 却没设 `windowsHide`，Windows 的规则是「父进程没有控制台 + 子进程 inherit stdio ⇒ 给子进程新建一个控制台」。

修法（两处，都不改第三方源码，避免跟着 NapCat 版本漂移）：

- 新增 `server/no-console.cjs`：通过 `NODE_OPTIONS=--require` 预加载进监视器进程，把 `child_process` 的 `spawn / fork / execFile / exec` 统一补上 `windowsHide: true`；末尾调 `module.syncBuiltinESMExports()`，让 `await import("child_process")` 解构出来的 `fork` 也是打过补丁的（NapCat 正是这么用的）。
- `server/engine.js`：新增 `_consoleEnv()` 拼 `NODE_OPTIONS` 并在启动监视器时注入；`_buildEntry()` 新增 `_fromBat()`，能从 `launcher.bat` / `start.bat` 里抠出真正的 `node xxx.mjs` 行直接跑，而不是 `cmd /c` 起一个 shell（走 cmd 必然弹框）。

已验证的四种情形：真实 NapCat、真实 SnowLuma 直启、SnowLuma 走 `launcher.bat`、路径含空格与中文——**全部无可见控制台窗口**。
