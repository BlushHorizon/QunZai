# 群崽 v1.4.12 · 下载提速

这一版只做一件事：**把更新下载从「龟速」修成「多线程飞起」**，顺手修掉一个藏了很久的启动器致命 bug。

## 多线程分段下载（移植自 PCL2-CE）

以前更新时是单连接顺序下载，国内直连 GitHub 只有 10~30 KB/s，80 MB 的包要下一个多小时，还会中途断掉。

现在 `app/server/fast-download.js` 按 PCL2（Plain Craft Launcher）的 AdaptiveRangeDownloader 思路重写：

- **Range 探测**：先 `bytes=0-0` 确认服务器真支持分段，不支持就整体退回单连接顺序下载（不影响功能，只是没提速）
- **分段并发**：默认 6 条连接、8 MB 一段同时下，各写各的文件偏移
- **慢段动态劈分**：某条连接持续低于其他连接中位数的 1/4，就把它的剩余区间再劈成两半丢回队列——这是 PCL 提速的关键一招
- **失败重试 + 降并发**：单段最多重试 2 次指数退避，遇 429 全局降并发
- **SHA256 / 大小校验**：边下边算，校验不过自动删掉 `.part` 并回退下一个源

实测（80.6 MB 安装包，ghfast.top 镜像）：**40.3 秒下完，6 线程，动态切成 15 段**，峰值 15.9 MB/s。原来单线程同一条链接只有 12.8 KB/s。

## 下载进度可见

更新时状态栏会实时刷新：`正在下载 v1.4.12… 33.8% ｜ 27.2/80.6 MB ｜ 6842 KB/s ｜ 6 线程`。
新增只读接口 `GET /api/update/progress`，只暴露百分比、速度、线程数，**不暴露下载地址**。

## 镜像优先 + 自动回退

更新清单里新增可选 `mirror` 字段。下载时先走镜像（国内快），镜像失败或校验不过就自动回退官方 GitHub 地址，用户无感。
`site/update.json` 已带 `mirror` 指向 `ghfast.top`。

## 修掉 launcher.ps1 的 BOM 致命 bug

排查时发现 `launcher.ps1` 在仓库里是 **UTF-8 无 BOM**，而 Windows PowerShell 5.1 在没有 BOM 时按系统 ANSI 代码页（简中 = GBK）读脚本，中文注释会把多字节字符切坏，直接语法报错：

```
所在位置 ...\launcher.ps1:22 字符: 1
+ } catch { }
+ ~
表达式或语句中包含意外的标记“}”
```

结果就是这个文件**从来没有成功运行过一次**（`data/launcher.log` 至今不存在），所有走 `launcher.ps1` 的入口（停止服务、守护重启、嵌入模式启动）都会失败。

已加回 UTF-8 BOM，并新增 `.gitattributes` 用 `*.ps1 -text` 禁止 Git 再做换行/BOM 转换，防止复发。实测：有 BOM → 正常执行；无 BOM → 语法报错。
